# ЛАБОРАТОРНАЯ №2. Инструмент контейнеризации Docker

# Требования

Написать простое приложение `REST api` или взять готовое на любом языке программирования.<br>
Установить `Docker`<br>
Написать `Dockerfile` и собрать.<br>
Написать `docker-compose.yaml` и запустить.


# 1) Подготовить окружение
Подключиться к ВМ master-0 и запустить `prepare.sh` сценарий.
```console
su -
chmod +x ./prepare.sh
./prepare.sh
exit
```
После того как сценарий отработал, переподключиться по ssh к ВМ master-0.

Попробовать загрузить образ:
```console
docker pull debian:13.3
```

Вывести список образов на файловой системе:
```console
docker images
```

В случае успеха, в списке появится загруженный образ.

# 2) Ознакомиться с самыми часто используемыми командами Docker и их опциями.
Попробовать на примере любого образа: загрузить, запустить, поставить на него пакеты, удалить, и.т.д.
* **docker pull**
* **docker images**
* **docker run (-p --rm -it -d -v --entrypoint --env)**
* **docker start**
* **docker stop**
* **docker rm**
* **docker rmi (-f)**
* **docker build**
* **docker commit**
* **docker cp**
* **docker ps (-a)**
* **docker save**
* **docker load**
* **docker logs (-f --tail)**
* **docker container/volume/network prune**

```console
docker build --help

```

> Поместить в background контейнер запущенный в интерактивном режиме можно комбинацией клавиш ctrl p q

# 3) Написать Dockerfile и собрать свое приложение

Примерное содержимое `Dockerfile` можно посмотреть в `LAB_3/applications/*/Dockerfile*`, можете добавить какие-нибудь best practice в свой манифест.<br>
В той же директории можете посмотреть пример простых REST api сервисов, также можете взять их за основу.

> Упаковать в образ можно любое приложение (предпочтительнее взять компилируемый язык), лучше использовать REST api приложение. Но это не обязательное требование и можете взять любой свой вариант.

Полученный образ должен запускаться и работать, журналировать свою работу в `stderr/stdout`, обрабатывать входящие запросы и возвращать ответы (если выбрали REST api).

# 4) Написать docker-compose.yaml и запустить сервисы

Для того чтобы удобно запускать образы, существует `docker compose`<br>

Нужно написать `docker-compose.yaml` манифест, в котором будет запускаться ваш собранный образ + добавить какой-нибудь еще, желательно чтобы он был как-то связан с вашим сервисом, а не просто висел в фоне.<br>

Это может быть база данных с которой взаимодействует ваш сервис или nginx, который будет проксировать запросы на ваш сервис.<br>
В общем желательно что-то подобное сделать.

Команды которые могут быть полезны для взаимодействия с docker compose:

Запуск в фоне всех контейнеров или конкретного:
```console
docker compose up -d <service>
```

Остановка конкретного контейнера или всех:
```console
docker compose down <servce>
docker compose down
```

Перезапуск контейнера:
```console
docker compose restart <service>
```

Остановка контейнера:
```console
docker compose stop <service>
```

Просмотр лога конкретного контейнера или всех:
```console
docker compose logs <service>
docker compose logs
```
